CS 320 Portfolio Reflection

In CS 320, I learned how important testing, automation, and quality assurance are in software development. For my portfolio, I included my Contact service files from Project One and my Summary and Reflections Report from Project Two. These artifacts show my ability to create unit tests, follow software requirements, and use testing strategies to help make sure a program works correctly.

To ensure that my code, program, or software is functional and secure, I start by carefully reviewing the requirements and making sure each part of the program matches what is being asked. I use unit testing to check that the code works as expected, including normal cases, invalid inputs, and edge cases. Testing helps me find errors early before the program is released. I also try to write clean and organized code, use validation where needed, and avoid allowing incorrect or unsafe data into the system.

I interpret user needs by reading the requirements closely and thinking about what the user is trying to accomplish. Instead of only focusing on the code, I try to understand the purpose behind each feature. For example, in the contact service, the user needed a way to create and manage contact information while making sure fields like ID, name, phone number, and address followed specific rules. I incorporated those needs by using validation and tests to make sure the program met the requirements.

When I approach designing software, I break the problem down into smaller parts first. I think about what classes are needed, what each class should be responsible for, and how the program should respond when something goes wrong. I also consider testing early in the design process because it helps me confirm that each part of the program works before moving on. This course helped me understand that good software design is not just about making the program run, but also making it reliable, maintainable, and easier to test.
